# Native original-operation commit and clock research — 2026-10-17

This is source-backed design preparation for B2/B5/B7, not a new installed policy or an executed database test. No hosted setting, transaction, provider or worker was changed.

A successful function result does not establish the surrounding transaction committed. PostgreSQL transaction termination belongs to supported top-level CALL/DO contexts; an intervening SELECT/function call restricts it. The ordinary function entrypoint must leave final COMMIT recognition to the transaction protocol and a later read. Do not add an internal COMMIT or label its pre-commit return as independently committed. [PostgreSQL17 transaction management](https://www.postgresql.org/docs/17/plpgsql-transactions.html).

A new Read Committed SELECT observes previously committed work, but a transaction also sees its own earlier uncommitted writes. Therefore a getter is only committed-original evidence when its contract excludes the writer transaction, binds the same immutable operation/command/scope/package, and observes the complete assembly through the approved primary endpoint. Two successive queries can use different snapshots; reconstructing one receipt from unrelated reads requires an explicit consistency design. Sequences are not rolled back, so they cannot establish a gap-free rollback-safe event allocator. [PostgreSQL17 transaction isolation](https://www.postgresql.org/docs/17/transaction-iso.html).

The full-width top-level xid8 can help identify the writing transaction. pg_xact_status distinguishes recent committed, aborted and in-progress transactions, but old discarded status returns NULL and prepared work remains in progress. Commit timestamps require an optional setting and their history is removed. These mechanisms are supplementary checks; they cannot replace retained exact originals or convert old absence into an authoritative abort. An unresolved COMMIT ACK stays unknown until original reconciliation succeeds. [PostgreSQL17 transaction information](https://www.postgresql.org/docs/17/functions-info.html#FUNCTIONS-TXID-SNAPSHOT).

Durability is a separate gate: asynchronous commit may acknowledge work before WAL reaches durable storage, and its setting at COMMIT controls that behavior. The native transport must freeze and test the actual transaction-level durability contract before claiming crash-safe handoff/cache release. A function-local setting that reverts before COMMIT is insufficient reasoning. No account-wide configuration change is proposed here. [PostgreSQL17 asynchronous commit](https://www.postgresql.org/docs/17/wal-async-commit.html).

For source/fence expiration, transaction_timestamp/now stay at transaction start; statement_timestamp stays at command receipt. clock_timestamp changes during execution. Final admission checks need the contract-selected actual server wall observation after relevant locks and work, while its calibration/clock-step assumptions remain explicit. None creates a monotonic process clock or a commit timestamp. [PostgreSQL17 current date/time](https://www.postgresql.org/docs/17/functions-datetime.html#FUNCTIONS-DATETIME-CURRENT).

Proposed ordered native cases: provisional result then ROLLBACK; getter called inside the writer transaction; delayed COMMIT with a concurrent getter; lost ACK followed by same-ID read; changed same-ID command; complete versus partial assembly; genuine final lock-delay expiration; and actual durability/driver settings at COMMIT. Preserve original budgets and no-write refusal snapshots. Decide the transaction/receipt wire before implementing authoritative B5/B7 joins.
