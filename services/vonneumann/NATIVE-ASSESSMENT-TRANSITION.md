# Independent assessment and common-window replay

PAPER-COMPACT-03B3C1, reviewed 2026-10-11. This is an offline semantic layer for
the separately versioned, eight-member, two-EMA GA provider model. It neither
decodes a checkpoint nor admits native commands. The complete03B3C gate remains
open until optimizer graph, RNG, selection, genotype and ancestry enforcement.

## Captures derived at their actual model point

The causal replay now produces private detached marks at three precise points:
early terminal after its liquidation and terminal cash assignment but before
retirement; first risk abort before later protective updates/liquidations; and
common-deadline completion after liquidation but before retirement/birth. Pause
and Stop mark the interrupted cohort before clearing pending intents. These
marks come from independent ordered replay, never from the requested following
assessment. They are omitted from both externally callable wrapper results.

The assessment layer derives integer-unit cash, original initial cash, reduced
cash ROI ratio, historical peak/drawdown, held/terminal-cash basis and closed-trade
count at those marks. ROI and drawdown round independently to binary64; fitness
then rounds the multiplication by2 and subtraction separately, matching the
existing model. No PostgreSQL float cast or decimal division substitutes for
these boundaries. This validates the inherited objective; it does not calibrate
its drawdown weight or claim that cash-only interrupted observations are scores.

An early terminal freezes the exact revision/time, score and source cursor.
Later retirement, unchanged quotes, finalization or interruption cannot rewrite
that snapshot. A completed window retains the original drawdown result and
termination time while setting completion only for the full ordered batch.
Abort retains earlier terminal evaluations internally, adds unscored zero-trade
placeholders for missing evaluations, and emits eight withheld provenance
records. Those records retain actual observed economics but publish no ROI ratio,
ROI score or fitness score, even when an earlier terminal was locally scored.

The layer derives ordered cohort/evaluation identities, the 3600-second common
deadline, warmup/start/completion/abort transitions, original source-at-start,
current source-at-finalization and the complete displayed evaluation mirror.
New populations start with no frozen assessment; recovery/restart cannot tell
the interrupted batch. Finalized records bind owner/run/generation/member order,
revision/time, execution profile, window identities, exact fitness/evaluation
policies, completion/eligibility/reason and measurement basis. Missing, duplicate,
reordered, invented or repeated assessment batches fail.

The unindexed completion/abort event must occur exactly once at the replay-derived
operation boundary. Indexed action events remain in their verified order.
Omitting, duplicating, moving or inventing a completion/abort event also fails,
even when the earlier layer accepts its shape and all economic operations.

## Primary-source research for the next optimizer gate

Python documents exact rational construction and reduced numerator/denominator
evidence. The SQL uses integer units and explicit binary64 rounding to match this
model's conversions. PostgreSQL provides exact numeric arithmetic and integer
quotient/GCD operations; its generic rounding functions are not the binary64
nearest-even contract used here. [Python Fraction](https://docs.python.org/3.12/library/fractions.html),
[PostgreSQL17 mathematics](https://www.postgresql.org/docs/17/functions-math.html).

CPython 3.12.14 stores MT19937 as 624 32-bit words plus an index. Integer seeding
splits the magnitude into 32-bit words, and `random()` combines two draws into a
53-bit value. The next gate must compare full state and exact consumption,
including twist/index boundaries; matching a seed alone is insufficient.
[Pinned CPython C implementation](https://github.com/python/cpython/blob/v3.12.14/Modules/_randommodule.c).

The pinned Python sampling implementation uses rejection-based integer draws
and pool sampling for this small population. Sampling one fixed asset can still
consume RNG state. Gaussian mutation maintains a cached second variate and uses
platform mathematical functions. Review actual seeded gene outputs and any
cross-platform uncertainty; do not quietly accept nearby genes or change the
existing model version. [Pinned Python sampling/Gaussian implementation](https://github.com/python/cpython/blob/v3.12.14/Lib/random.py).
Python's reproducibility guarantee is narrower than unchanged behavior for every
high-level algorithm across versions, so the model's software pins remain part
of the contract. [Python reproducibility notes](https://docs.python.org/3.12/library/random.html#notes-on-reproducibility).

**Deep substantial research still required:** full optimizer graph schema and
semantic alias/order comparison; independent seed/state/tournament/crossover/
Gaussian mutation proof with stable tied fitness; bounded rejection and resource
behavior; objective sensitivity, holdout/multiple-seed/multiple-testing and
minimum meaningful window/trade counts; server-owned version-bound immutable
validation reuse; contended locks/TOAST/COMMIT/WAL and hosted latency/budget tails.
Synthetic fixtures establish implementation behavior, not profitability.

An implementation decision remains: if exact existing Gaussian portability

That is a research option, not an implemented change or permission to relabel
