# Owner-separated terminal retirement laboratory

This private source packet layers a held SQL companion on the exact accepted
SCRAM source. It leaves the SCRAM core SQL, constructor loader and finite
policy unchanged. It changes only the two fixture files and adds one SQL
postimage. All 45 inherited method bodies are byte-identical. Default and
SCRAM-only fixture modes do not load the overlay.

## Scope and authority

The anchor owner owns one bounded nullable permit on the existing package
row, the staging function and the deferred marker trigger. The native owner
owns a read/lock verifier that can see the reserved head, complete source
catalog and original writer identities. The overlay is installed by separate
owner roles in one bootstrap transaction. The fixture independently checks
all three held function bodies, headers, argument and return identities,
settings, exact EXECUTE grantors, the bounded permit column, trigger and
closed issuer privileges before accepting the new catalog digest.

The new USAGE and EXECUTE crossings are issuer to anchor stage, and anchor
owner to native verifier. Neither crossing grants table access, role
membership, native runtime entry points or permission to change the owner.
The separate limited issuer and all actors use actual direct SCRAM over the
existing owned TLS fixture with hostname verification and required channel
binding. Their synthetic credentials are not hosted credentials. This proof
keeps the issuer trusted over its actor passwords. It does not purport to
contain arbitrary administrative DDL.

The trusted anchor fixture preauthorizes exactly the scope-0 position-three
original Stop and the two historical writer bindings. Its permit has an
explicit identity, canonical wire, original Stop, catalog/package digests,
issuer OID and database expiry. The stage locks package, sorted writer binding
rows and scope head in that order. The native verifier derives both writers
from finalized Install and Acquire, checks their binding/role/canonical
manifest association and exact pre-retirement K, and verifies live control
and reader lifetime. The stage writes only the expected terminal marker.
The marker represents permit consumption. The issuer then performs the two
fixed `ALTER ROLE` statements in that transaction. The marker trigger checks
recognized literal COMMIT, exact retired roles and catalog with only their
LOGIN bits projected, and the original held head. First provisioning of a
permit without a marker does not trigger retirement. Once set, ordinary
DML cannot replace the permit or clear the marker through this procedure.

## Expected native observations

1. The separate closed setup case verifies the scoped function count, two
   uninstalled scope heads, absent permit/marker and issuer schema boundary.
2. The role/lock case installs, acquires and resumes using actual actors.
   Deny issuer owner assumption, direct table/lock-helper access, worker
   staging or role administration, anchor native-table read, native anchor
   update and using the same permit for the other scope.
3. Stage the reserved Stop in a competing control transaction. The actual
   limited issuer's package NOWAIT must refuse with `55P03`. Roll back the
   pending control transaction. The snapshot remains unchanged.
4. Require early `SET CONSTRAINTS ALL IMMEDIATE` refusal before DDL and after
   witnessing both disabled logins. A literal COMMIT after witnessing only
   the first disabled login must fail. Every negative preserves the permit,
   absent marker, original rows, both login bits and exact original readback.
5. On the exact authorized literal COMMIT, witness both disabled roles, the
   exact committed marker and no native row changes through an independent
   fixture observer. Deny permit reuse, fresh writer login and modified Stop.
   The live control commits the reserved original at position four. The live
   independent reader obtains its exact original receipt on repeat lookup.

The observer is the owned fixture administrator. This adds no independent
production permit-reconciliation API, managed installer, password handoff,
ongoing generation replacement or multi-scope activation. The exact terminal
case is one open scope at position three and uses the existing bounded Stop
branch. Closing economic positions or broader source capacity is separate.
