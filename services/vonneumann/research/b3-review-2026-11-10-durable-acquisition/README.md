# Native durable acquisition fixture

This candidate exercises PostgreSQL reservation and capture in a dedicated test fixture. The [forward patch](candidate-forward.patch) adds three fixture paths to base `f317ffc4519d5a70002279458992e54465a9821f`, tree `3eb3469b0d4eb4e4d7993d202fc54909bff9da89`. The [manifest](manifest.json) pins all three files, six source dependencies, the 939-file composition, and the two test IDs. Applying the patch reproduced every candidate byte.

The fixture accepts one unresolved reservation for one synthetic SOL/USD scope. An allowed recorder reserves nine identities under the scope lock and binds the exact A1 Reservation and actual `PreparedPacket` wires. The recorder grants one in-memory collection callback only after acknowledged transaction success and a separate getter verifies the exact committed reservation. Replaying the same reservation supplies no grant. A fresh recovery reader exposes only the independent getter and requires no locally retained Capture bytes or digest. The capture is retained in a separate transaction. It supplies neither source admission nor terminal closure, so cache release stays gated in every state.

The fixture SQL checks role and scope, exact envelope keys, canonical wire ordering, the held false authority flags, matching identities and hashes, and exact raw byte length, Base64 and digest. The Python recorder and independent reader apply the existing A1 capture and capsule validators. The collection callback supplies three fixed synthetic response bodies. Native interpretation of raw provider data and source admission remain separate steps.

Both native cases passed in 2.868 seconds on disposable PostgreSQL 17.6 with no network. The tests used separate trust-socket recorder and reader roles. Each termination matched the exact fixture backend by database, role, PID, backend start, application name, and observed sleep statement. After a separate read witnessed Capture COMMIT, the writer backend terminated and a fresh reader recovered the original capture, all three raw bodies, and its receipt. The collection callback ran once, and a competing reservation refused. In the pre-COMMIT case the getter returned `observed_absent_unknown` after the writer backend terminated. The reservation stayed unresolved and blocked replacement. Both cases verified the full retained rows and the count of nine reserved identities. [Native receipts](native-receipts.json).

All 55 existing offline provider and source-admission cases passed. A mock caller separately exercised one-use grant consumption, lost acknowledgment, missing independent witness, the existing-reservation refusal to mint a new grant, and the fresh read-only boundary.
