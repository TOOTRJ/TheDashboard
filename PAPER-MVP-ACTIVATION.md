and lease remain usable, request its existing reserved stop; settlement reuses
the original command/event identities. A stop preserves open holdings and cash.
Never start a new run or synthesize liquidation to hide an uncertain outcome.

remove only this operation's native/provider/control additions. Revoke each

The release transition supports closed→open and open/closed→retired only.
Retirement is an optional one-way database admission shutdown after admitted
transactions settle. It preserves all data and denies legacy writers; it cannot
be undone by changing the epoch or starting a new worker. If needed, prepare a
separate original-ID transition with a rollback evidence digest and verify its
receipt. A later release after retirement requires a separately reviewed forward
change. Routine canary failure can instead leave runtime closed and all finite
pairs revoked while the installed release remains open with no worker authority.
